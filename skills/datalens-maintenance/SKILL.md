# DataLens Maintenance

Paginate inventory completely within the requested scope and describe backup completeness honestly. Before cleanup compute the dependency preserve closure and show the exact delete set. Use documented HTML Page, workbook, access, and license operations only; never invent a revoke route or browser write fallback.

Use this skill for backup, administrative inventory, and dependency-safe cleanup. Route ordinary object inspection to `datalens-inspect` and authoring to the Dataset/Wizard, dashboard, or Editor skill. Load only the boundary reference needed by the requested maintenance operation.

Read [references/boundaries.md](references/boundaries.md) before backup, cleanup, HTML Page, or license work.

Cleanup identity is the provider entry ID regardless of inventory aliases. Preview reads both dependency directions, preserves the original roots, orders consumers before dependencies and rejects incomplete or external-consumer scope. Apply revalidates the original scope before any write; `preview_changed` requires reconciling the fresh preview with the authorized scope and preserve requirements. Failed/uncertain deletion stops all remaining objects and returns per-object skipped/partial effects. Do not retry an uncertain write or recreate deleted objects. A previous authorization covers only its exact scope; a destructive scope outside the current request requires user authorization. `confirmed_delete` records the exact machine scope; an already explicit deletion request needs no new human reply. Preview is bounded to API-visible relations and must not be described as proof of tenant-wide completeness.

Follow [authorized scope and delivery](../datalens-dashboard/references/authorized-scope.md) for mutations: explicit scoped work continues without repeated permission questions; read-only and save-only limits remain binding.
